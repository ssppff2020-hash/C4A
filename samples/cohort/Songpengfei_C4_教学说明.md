# Songpengfei C4 教学说明：lesson-design-assistant 上手指南

> 目标读者：任何想用本技能备课的教师/培训师/同学。读完本文，你应该能独立完成一次教学设计。
> 版本：**v2**（新增教案校验器与 5 分钟教学脚本）

---

## 〇、如果你只有 5 分钟教别人（照着念就行）

> 对方是完全没用过 AI 技能的同事。按下面 4 句走，5 分钟他能独立跑通：

1. **"你平时写教案最烦哪一步？"**（多半答：从零搭结构 / 每次格式都不一样）
2. **"那给你一句话就行的工具——你说：写一份《XXX》的教学设计，对象是 XX 专业 X 年级学生。"**
3. 等他看到 8 段式教案出来后，说：**"不满意的地方直接说，比如『把导入换成一个真实企业案例』。"**
4. 最后补一句杀手锏：**"写完了还能自检——把教案丢给校验器，它会告诉你哪段不合格。"**

**关键**：全程不要讲"技能""工作流""SKILL.md"这些词，只讲**他备课的痛点**和**他面前这一份教案**。

## 一、三步上手

### Step 1 — 安装技能
- 方式 A（推荐）：将 `Songpengfei_C4_lesson-design-assistant.skill` 安装到支持 Claude Skills 的客户端，安装后直接对话触发。（该文件为 ZIP 格式，与官方两个样例技能一致；若你的环境要求 tar.gz，用附带的 `.tar.gz` 版本。）
- 方式 B（不装也能用）：解压 .skill，把 `SKILL.md` 内容贴给任意 AI 助手（连同 `references/design_framework.yaml` 一起效果更好），同样可用。
- 方式 C（只用脚本）：`python scripts/lesson_design_template.py --topic "主题" --audience "对象" --duration 45`，先拿骨架再手动/让 AI 填充。

### Step 2 — 说一句触发话术
```
写一份《数据结构—栈》的教学设计，对象是计算机专业大二学生，已学 C 语言。
```
也可以更详细：
```
帮我设计《管理学原理—激励理论》这节课，2 学时，50 人，已学管理职能，
希望多案例分析，加入课程思政。
```

### Step 3 — 拿到 8 段式教案后，按需修订
- "把第二个环节改成任务驱动"
- "导入环节换成一个真实企业案例"
- "把目标改得更可测量"
- "输出中英文双语版"

### Step 4 — 自检（v2，强烈建议做）
```bash
python scripts/lesson_check.py 你的教案.md
```
- 输出 0–100 分 + 7 项逐条结论 + 改进建议。
- 有 ❌ 就回到对应环节改，再跑一遍，直到通过（退出码 0）。
- 加分项：`--json` 输出可接 CI，教案仓库每次提交自动拦截不合格教案。

**校验器会检查什么**：① 8 段是否齐全且**真的填了内容**（空骨架会被打回）② 目标动词是否可测量 ③ 环节时长合计是否 = 课时 ④ 知识/能力/素养三类目标是否都被评估覆盖 ⑤ 是否含过程性+结果性评估 ⑥ 学情推测是否标注【假设】⑦ 是否附自查清单。

## 二、常见坑（重点看）

| 坑 | 现象 | 解决办法 |
|----|------|----------|
| 目标不可测量 | 写了"学生掌握栈" | 要求 AI 改为布鲁姆动词："学生能够用 C 语言实现入栈/出栈操作" |
| 环节时长对不上 | 五段时长加起来 ≠ 课时 | 让 AI 重新核算时间轴，或直接看校验器 C3 项报的差额 |
| 目标无对应活动 | 目标写了但环节里没有 | 要求 AI 做"目标-活动对齐检查" |
| 学情靠猜 | 学情分析全是假设 | 让 AI 标注【假设】，课前用问卷/前测验证 |
| 思政生硬 | 思政点与内容脱节 | 要求 AI 说明思政融入点的设计意图 |
| 教案太长 | 一次输出过多 | 让 AI 先出大纲再逐段展开 |
| **只交骨架不填内容**（v2 新增） | 运行骨架脚本后直接把空表交上去 | 校验器会把空骨架判 **40 分 ❌**，明确列出哪几段没填 |
| **Windows 控制台中文乱码**（v2 新增） | 脚本输出的中文变成"��" | v2 脚本已内置 UTF-8 输出兜底；若仍乱码，先执行 `chcp 65001` |

## 三、优化技巧

1. **先骨架后填充**：对复杂课程，先用脚本生成骨架 → 再让 AI 逐段填充，避免一次输出过长导致质量下降。
2. **喂真实学情**：把班级人数、前测结果、作业情况粘贴给 AI，学情分析会更贴近实际。
3. **用自查清单验收**：每次输出末尾的自查清单是质量闸门，4 项全勾才算合格。
4. **迭代存档**：把 v1、v2 教案都存好，对比差异能看出教学设计的进步轨迹，也是教学比赛的好素材。
5. **复制到学校模板**：把 8 段式内容复制进学校规定的教案模板，只需调整格式，内容直接用。

## 四、一分钟自检表（交付前核对）

- [ ] 8 段结构齐全（基本信息/学情/目标/重难点/环节/方法/评估/反思）
- [ ] 目标动词可测量
- [ ] 每个目标至少对应 1 个环节
- [ ] 评估覆盖全部目标
- [ ] 学情假设已标注
- [ ] 环节总时长 = 课时长度

> 这 6 项里有 5 项（8 段完整、目标可测量、评估覆盖、学情假设、时长一致）
> 可以直接交给 `lesson_check.py` 自动查，不用手工核对——手工只保留"每个目标是否都有活动支撑"这一项人工判断。

## 五、常见问题（FAQ）

**Q：我不会编程，能用吗？**
能。脚本只是可选项，纯对话就能完成全部工作。

**Q：生成的是"教案"还是"教学设计"？**
两者都要：8 段式覆盖教学设计全部要素，可直接用作教案；教学大纲类需求可在目标与环节基础上扩展周次计划。

**Q：和直接问 AI"帮我写教案"有什么区别？**
直接问 AI 得到的教案结构随机、要素不全；本技能强制 8 段结构、布鲁姆目标、目标-活动-评估对齐，并附自查清单，产出更规范、可评审、可复用。

**Q：怎么验证技能真的有用？**
用本文"真实案例"的输入跑一遍，对比输出是否含 8 段；再拿一节你正在备的课试一次，感受从 2 小时到 10 分钟的效率提升。

**Q：校验器会不会永远给我满分，没什么用？**
不会。实测：合格教案 100 分、**未填充的空骨架 40 分 ❌**、缺段+超时+目标含糊的教案 26 分 ❌。
它的价值恰恰在于"会报错"——只会打满分的检查器没有意义。你可以自己造一份残缺教案试试。

**Q：校验器说我不合格，但我觉得教案没问题？**
校验器只管**能机械判断的部分**（结构、时长、对齐）。它会因为"目标写了'掌握'这种不可观测动词"或"环节合计 35 分钟 ≠ 课时 45 分钟"而报错——这两类确实是督导会挑的问题。
反过来，它管不了"学情是否真实""案例是否贴切"，那部分仍需你自己把关。

**Q：教案是 PDF / Word，能校验吗？**
脚本只吃 Markdown 文本。先把正文复制粘贴成 `.md`，或用 AI 转一遍格式再校验。
